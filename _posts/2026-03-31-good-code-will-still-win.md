# Good code will still win - 良いコードは勝ち残る
AI時代でも「雑コード（slop）」に負けない、現場で使えるシンプル戦略

## 要約
AIによる大量生成コード（いわゆる「slop」）が増えているが、経済的・運用的理由から「良いコード（シンプルで保守しやすいコード）」が最終的に勝つ、という主張の要約。

## この記事を読むべき理由
AI補助開発が日本でも急速に普及する中で、速さだけを追う運用は障害や保守コスト増につながる可能性が高い。日本の企業文化や長期保守重視の案件では特に、良いコードをどう守るかが競争力の差になるため、現場で役立つ視点を得られます。

## 詳細解説
- 「slop」とは、AIが量産する意味の薄い・乱雑なコードのこと。最近の傾向として、AIの導入でPR数やコミットあたりの差分サイズが増え、コード量が急増している観測がある。  
- その結果、サービスの脆弱化や停止が増え、抽象化の肥大化・コピペ的なコード増殖といった問題が報告されている。  
- John Ousterhoutの「複雑さは最大の敵だ」という考えが示すように、良いコードは少ない文脈（＝理解コスト）で修正・拡張でき、長期的には総コストが低くなる。  
- AIが生成するコードも、最終的には「トークン（入力・出力の情報量）と計算コスト」を抑えた設計を出すモデルが競争で有利になる。つまり、経済的インセンティブが働けば、AIはシンプルで保守しやすいコードを書く方向に進化すると予想される。  
- 現段階は高速に実装して動かすフェーズで混沌としているが、普及が進むにつれ「良いコード」が評価される市場環境が整うと著者は結論付けている。

## 実践ポイント
- アーキテクチャを後回しにしない：短期的な実装より境界と責務の設計に時間をかける。  
- PRを小さく・頻度高く：差分を小さくすればレビューと巻き戻しが容易。  
- 自動化された品質ゲートを導入：静的解析・型チェック・テストをCIで必須化する。  
- AIツールにルールを与える：コーディング規約・テンプレート・コンテキスト制約を設定して雑生成を抑制。  
- 独立したコード監査を持つ：AI生成コードのレビューを人（または別のツール）で俯瞰的にチェックする。  
- メトリクスを追う：PRサイズ、障害頻度、復旧時間などを計測して「slop化」の兆候を検出する。

短期の速度と長期の維持性を両立させる実務習慣を今のうちに整えれば、AI時代でも良いコードが「勝つ」ことを現場で確かめられます。
