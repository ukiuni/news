# Linear types proposal for Hare - Hare向け線形型提案
現代のリソース管理をHareに：「使い捨て型」でバグとメモリ漏れを根こそぎ防ぐ方法

## 要約
線形型（linear types）を導入することで、ファイルやポインタなど有限リソースの「所有権」を型システムで厳密に管理し、リークや二重解放、use-after-free をコンパイル時に防げる仕組みを提案しています。

## この記事を読むべき理由
Rustの所有権/借用と似た安全性をHareに持ち込みたい開発者や、日本の組み込み・サーバー開発でメモリ安全性を高めたいエンジニアにとって、設計思想と具体的メカニズムが学べます。

## 詳細解説
- 基本概念  
  - 線形型(linear)：値は1回だけ使える（コピー不可）。ファイルなど有限リソースを表現。  
  - 自由型(free)：コピー可の基本型（i32, bool等）。線形型を含む型は線形としてマーク必須。

- 所有権と参照の使い分け  
  - 消費する操作は値を受け取り消費する（例: close(f: file)）。一方、操作のみ行う場合は参照を使う（write(&file)）。  
  例:
  ```hare
  fn correct() void = {
    let f = open("thing");
    write(&f, "123");
    close(f);
  };
  ```

- 制御構造への適用  
  - if/loop の各分岐で「必ず消費される」かを検査。可能性のあるリークや反復内での二重消費はコンパイル時エラーになる。

- 複合型の破棄  
  - Hareは析構子がないため、内部フィールドを個別に閉じる設計。型をvoidにキャストして完全破棄を表現。

- 配列／スライス操作（重要）  
  - 配列は全要素の有効性を保つ必要があるため、原子的な型システム操作を導入。  
  - atomic swap: 値を置き換え元の古い値を返す `old = value <- new`。例:
  ```hare
  close(files[0] <- open("a")); // 古い files[0] を閉じてから置換
  ```
  - atomic free: スライス全体や範囲を走査して消費する `free(files, &close)` / `delete(files[2..5], &close)`。

- スライス確保とappend  
  - 線形要素はデフォルト値で初期化できないため容量指定でallocしappendで埋めるパターンを推奨。

- ポインタ vs 参照  
  - スタック参照(&)はfree（コピー可能）で、ヒープポインタ(*)は線形（消費される）。ポインタ→参照は可能だが逆は不可。参照は元のストレージに依存する。

- エラーハンドリングと defer?  
  - 従来のdeferだけでは線形値のリークにつながるため、条件付き defer（`defer?`）を導入。エラー経路でのみ安全に解放を登録できる。

- 借用スライス／文字列とライフタイム注釈  
  - 借用スライス ` [&]T ` と所有スライス ` []T ` を区別し、参照の寿命をプロトタイプで `^name` 注釈で指定。関数の引数→戻り値の依存関係を明示して安全性を保証。

## 日本市場との関連性
- 組み込み・IoT開発や低レイテンシ金融系サービスではメモリ安全は必須。C/C++での運用負荷やバグコストを下げる手段として、Hareに線形型が来れば採用の敷居が下がります。  
- 日本の技術スタックでRust採用が進む一方、Hareのような軽量言語に同様の所有権モデルが入れば、小〜中規模のシステムで高速かつ安全な開発が可能になります。

## 実践ポイント
- 小さなライブラリで試す：ファイルやソケットを扱うモジュールから線形型を導入して挙動を観察する。  
- 配列操作は atomic swap / free を意識して実装する（既存コードの置換でリーク検出が有効）。  
- defer? を使ってエラーパスでのリソース解放を明確にする。  
- 参照とポインタの寿命注釈をプロトタイプに付け、APIの使い方をドキュメント化する。  
- Rust経験があれば概念移行は容易：所有権→線形、借用→参照、と理解して試す。

短く言えば、Hareに線形型が入ると「コンパイル時にリソース管理不備を捕まえる」ことで、バグと運用コストを減らせます。まずは小範囲で試してみてください。
