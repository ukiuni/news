# Windows 95 defenses against installers that overwrite a file with an older one - インストーラーが古いファイルで上書きするのを防いだWindows 95の仕組み
「勝手に古いファイルで上書きされる」地獄を救った、Windows 95の舞台裏

## 要約
Windows 95は、サードパーティ製インストーラーがシステムファイルを古いバージョンで上書きして壊す問題に対し、インストール後に差分をチェックして自動で復元・保護する仕組み（SYSBCKUP）を導入して回避した。

## この記事を読むべき理由
古い設計がもたらす互換性トラブルは現代のパッケージ管理や組み込みコンポーネント配布にも通じる教訓です。インストーラーや配布物を作る開発者、運用者、テスト担当者が「何を守るべきか」「どう防ぐか」を学べます。

## 詳細解説
- 問題点  
  かつてはアプリが必要なシステムコンポーネントを自身のインストーラーに含め、単純にファイルをコピーしていた。推奨は「既存のバージョンと比較して新しい場合のみ上書き」だが、実際はバージョン無視で上書きするインストーラーが多く、Windows 95の新しいコンポーネントが古いものに置き換えられてシステムが壊れた。

- Windows 95の対策（SYSBCKUP）  
  1. よく上書きされるシステムファイルのバックアップを隠しフォルダ（例: C:\Windows\SYSBCKUP）に保持。  
  2. インストーラー終了後に差分チェックを行い、置き換えられたファイルを検査。  
  3. もし置き換え後のファイルがバックアップより新しければバックアップを更新し、古ければバックアップから復元することで、悪影響を修正。  
  この「後からチェックして直す」方針は、上書きを事前に阻止してエラーや無理な再起動を引き起こすより現実的だった。

- その他の試みと課題  
  事前ブロックだとインストーラーが失敗してユーザーに選択を迫る、またはバッチ再起動で無理やり上書きしようとするケースが発生。チェックサム検証を行うインストーラーもあり、単純なリダイレクト対策では対応できなかった。

- 派生的な対策  
  一部コンポーネントは独自のインストーラーを提供し、他のインストーラーが直接ファイルを置けないポリシーにした（信頼できないインストーラー作者対策）。

## 実践ポイント
- インストーラー作成時は必ず既存ファイルのバージョン／署名を確認し、古ければ上書きしない。  
- 共有コンポーネントは専用インストーラーやバージョン管理された配布（サイドバイサイド）で提供する。  
- 予期しない上書きに備えてインストール前後にバックアップと差分チェック（テスト用VMでの検証）を行う。  
- ユーザーに技術的判断を求めるダイアログは避け、インストーラー側で安全なデフォルトを選ぶ。  
- 既存環境を壊さないために、インストール処理はトランザクション的に設計し、ロールバック手段を用意する。

このエピソードは「互換性と配布の現実」を考える良い教材です。古いWindowsの苦労は、現代のパッケージやドライバ配布にも活かせます。
