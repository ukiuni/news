# We've raised $17M to build what comes after Git - $1,700万調達、"Gitの次"を作る

Gitの枠を超える「次世代のバージョン管理」とは？──GitHub共同創業者が立ち上げたGitButlerが、a16z主導で$17Mの資金調達を発表し、AI／エージェント時代に最適化された開発基盤の構築を加速します。

## 要約
Gitは20年でソフト開発の基盤になったが、AIや複数のエージェントと並列で動く現代の開発には限界がある。GitButlerは「Gitの置き換え」ではなく、既存プロジェクトに導入できるCLIやワークフローを通じて、コンテキスト維持と協調作業を再設計しようとしている。

## この記事を読むべき理由
日本の開発現場でも、トランクベース開発やAIアシスタントの導入が進む中で、マージ衝突・コンテキスト断絶・レビュー負荷といった課題は顕在化しています。GitButlerのアプローチは、これらに実践的な解決策を提供する可能性があります。

## 詳細解説
- 資金と背景：GitButlerはa16z主導のSeries Aで$17Mを調達。創業者のScott ChaconはGitHub共同創業者で、長年の経験から現行Gitモデルの限界を指摘している。  
- 問題定義：Gitは元々「パッチ送付」向けの設計で、今は複数人・複数エージェントが同時に変更を起こす前提になっていない。課題は「コード生成」自体よりも、変更の整理・レビュー・統合にある。  
- GitButler CLIの狙い：  
  - GitHub Flowや短命ブランチ、トランクベース開発に向けて設計。  
  - 「スタックされたブランチ（stacked branches）」やマルチタスク、容易な元に戻す操作などで並列変更を整理。  
  - 人間とエージェントの双方に使いやすいインターフェースを目指し、既存のGitプロジェクトへドロップイン可能。  
- ソーシャル化の試み：PR説明やエージェントの対話、関連会話など失われがちな文脈を可視化し、早期にマージ衝突を検出・通知することでチームの協調を高める。  
- 方針：単なる「より良いgit」ではなく、次世代のソフトウェア開発インフラを構築するという立場。

## 実践ポイント
- 今すぐ試す：公式の技術プレビュー（GitButler CLI）を既存リポジトリで試し、トランクベースや短命ブランチ運用との親和性を確認する。  
- ワークフロー設計：スタックブランチや並行レビューの運用ルールを小さなチームで検証し、効果と注意点を測る。  
- エージェント統制：AIアシスタント導入時はアクセス制御・ログ管理・データ扱いの方針を事前に整備する。  
- 日本市場での応用：モノリポ／大規模チーム、リモート分散開発、エンタープライズのコンプライアンス要件に合わせた導入検討を。  

短期では「導入の試験」、中長期では「チームのコラボレーション設計とエージェント運用ポリシー整備」が鍵になります。
