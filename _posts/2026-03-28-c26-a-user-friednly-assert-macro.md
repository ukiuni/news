# C++26: A User-Friednly assert() macro - C++26: 使いやすくなった assert() マクロ
C++の小さな“イライラ”を解消するアップデート──初心者にも優しいassert()へ

## 要約
C++26ではassert()が冗長な括弧やカンマで壊れやすい問題を解消するため、可変長マクロに変わります。これにより普段使いのアサーションがより直感的で堅牢になります。

## この記事を読むべき理由
日本のプロジェクトや教育現場でもassertは頻出です。ビルドエラーの原因が「見えないプリプロセッサの挙動」だった経験は多く、今回の改善は日常的な生産性向上に直結します。

## 詳細解説
従来のassertはマクロであり、引数解析はプリプロセッサの単純なカッコ解析に依存します。そのためテンプレートの角括弧や、ラムダ・中括弧・カンマを含む式で意図せずコンパイルエラーになることがありました。例：

```C++
using Int = int;
int x = 1, y = 2;
assert(std::is_same<int, Int>::value);                 // 角括弧が原因で失敗することがある
assert([x,y]() { return x < y; }() == 1);             // カンマで壊れる
assert(std::vector<int>{1,2,3}.size() == 3);         // 中括弧で壊れる
```

提案P2264R7ではassertを可変長マクロ（__VA_ARGS__）に変え、assert(...)の形にすることで上記がそのまま動くようになります。診断メッセージをカンマで付ける案は却下され、トップレベルでのカンマ使用を禁止する設計になりました。代わりに文字列リテラルを && で繋ぐ形でメッセージを与えます：

```C++
assert(x > 0 && "x was not greater than zero");
```

契約（contracts）が普及してもassertが不要になるわけではなく、既存コードや簡易チェックとしてアサーションは残ります。互換性も保たれ、従来の使い方は壊しません。ただし（記事執筆時点で）主要コンパイラのサポートはまだ広くはありません。

## 実践ポイント
- 当面の対処：現状のコンパイラで問題が出る場合は追加の括弧で回避する（例: assert((expr));）。
- メッセージ付与は && を使う（assert(cond && "message");）。カンマによるメッセージは避ける。
- 新機能が使えるかはコンパイラのバージョンを確認する（C++26対応が必要）。
- 社内ライブラリでは、C++26未対応環境向けに安全なヘルパーマクロを用意しておくと互換性管理が楽になります。
- 教育現場では「プリプロセッサはC++構文を理解しない」点を併せて教えると詰まりにくくなります。
