# Rust's next-generation trait solver - Rustの次世代トレイト解決器
循環参照を「賢く見切る」新コンパイラ設計 ― より速く、より柔軟なトレイト解決へ

## 要約
Rustのコンパイラはトレイト解決器を全面的に書き換え中で、循環する依存関係をプロビジョナル（仮）キャッシュで扱えるようにして、将来的にコンパイル速度と表現力を改善することを目指しています。

## この記事を読むべき理由
- ジェネリクスやライブラリ設計で直面する「トレイト解決の限界」が緩和され、より抽象的で柔軟なAPI設計が可能になります。  
- 日本のクレート（サーバー、組込み、ゲーム、工具類）を保守する開発者は、nightlyフラグの影響や安定化までの互換性確認が必要です。

## 詳細解説
トレイトは型に対する共通の振る舞いを定義します。コンパイラのトレイト解決器は「どのimplが実際に使われるか」を決定する部分で、ジェネリック型では依存関係が連鎖して「義務（obligations）」が発生します。従来の解決器はこの義務を順に処理するが、複雑なジェネリックや自己参照的な型で義務がループすると「overflow evaluating …」のようなエラーで失敗します。

例（概念的）:
```rust
// 概念例：Vec<T> が Clone であるのは T: Clone のとき
impl<T> Clone for Vec<T> where T: Clone { /* ... */ }
```
より複雑な例では型の関連型やラッパーを介して義務が自身に戻り、従来はそのループを解けませんでした。

経緯と新設計：
- 2015年からの研究（Chalk）で得られた論理推論の知見を取り込みつつ、2023年からコンパイラ内で書き換えが進行。
- 次世代トレイト解決器は「プロビジョナル（仮）キャッシュ」を使う：解決を始めるとまず仮の真とマークし探索を進め、探索の終点が仮の参照だけで成り立つ場合にそれらを本当に昇格（coinductive扱い）する。失敗なら仮エントリは破棄され別ルートを試す。
- これにより「生産的（productive）」な循環（安全に扱える自己参照）は許容され、誤った帰結を避けるために誘導的な（unsoundな）循環は引き続き拒否されます。
- キャッシュ重視のため「正規化（canonicalization）」で型変数を減らし、証明ツリーをキャッシュから復元して詳細なエラーメッセージを出せるようにしています。
- 現状：coinductive扱いは一部組み込みトレイト（例: Sendなど）に限定。-nightlyで -Znext-solver=globally を試せるが安定化前に互換性や性能問題の検証中（Craterテスト等）。既知のバグは多数残るが着実に解消中。

## 実践ポイント
- まずは nightly で試す: -Znext-solver=globally を使って自分のクレートをビルドし、ICEや挙動変化を報告する。  
- 安定化前は新仕様に依存した設計を避ける（ライブラリ公開物は互換性を重視）。  
- 抽象度の高い自己参照的APIを検討しているなら、今回の進展で将来は手放しで書ける可能性がある。  
- パフォーマンス／エラーメッセージの変化を注視し、問題を見つけたらリポジトリやRustのissueに具体例を提出する。  

元記事は実装の細部や循環の理論（帰納的 vs 共帰納的）についてさらに踏み込んでいます。興味があれば nightly を試してみてください。
