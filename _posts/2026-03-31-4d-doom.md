# 4D Doom - 4Dドゥーム
超次元で遊ぶDOOM風ゲーム？——4次元迷宮を切り裂くWebGPUデモ「HYPERHELL」

## 要約
ブラウザで動く「世界初級」とされる4次元DOOM風デモ。WebGPUを使い、4次元空間を「4D Eye（3Dセンサーを持つカメラ）」としてレンダリングする新しい手法で、プレイヤーは次元のズレを利用して進む。

## この記事を読むべき理由
4D表現はゲーム・可視化・教育での新しい表現領域です。日本のゲーム開発者／研究者／学生にとって、ブラウザで動く実装例は学習コストが低く実験・プロトタイプにすぐ使えます。

## 詳細解説
- プロジェクト概要：GitHub上のHYPERHELLはHTML＋JavaScriptで作られ、WebGPUレンダリングを前提にした4次元世界のデモを公開。アセットや4D生物のデータがリポジトリに含まれる。
- 4Dレンダリングの肝：「4D Eye」は4次元空間を直接「撮る」発想で、4D→3Dのセンサー出力を生成し、それを通常の3Dカメラで可視化するような手順を取る（いわば4D空間のスライスや射影を3Dデータに変換）。
- ゲーム性：「Unblink」メカニクスなど、プレイヤー操作で視点や次元表現を変えるインタラクションを用意。物語要素（Bargainer）で次元変化の選択をプレイヤーに委ねる。
- 技術スタック：WebGPUベースのレンダリング（ブラウザ側のGPUアクセラレーション）、クライアントはHTML/JS。動作確認はMacBook M1/M2やNVIDIA GPU＋Chromeで報告あり。

## 実践ポイント
- まずデモを試す：リポジトリのページからPlay the Demo Online（WebGPU対応ブラウザで）。
- ローカルで動かす（簡易手順）
```bash
git clone https://github.com/danieldugas/HYPERHELL
cd HYPERHELL
python3 -m http.server 8000
# ブラウザで http://localhost:8000/index.html を開く（WebGPU対応のChromeなど）
```
- 日本での応用例：ゲームの次元表現実験、大学の可視化演習、WebGPU採用検証（軽量プロトタイプとして最適）。
- 注目点：4D→3D変換アルゴリズム、UIでの次元操作設計、ブラウザベースでのGPU利用に伴う互換性チェック（WebGPU対応状況を確認）。

元リポジトリ（ソース・README・デモ）を眺めるだけでも、4Dレンダリングの実装アイデアが豊富に得られます。興味があればローカルで動かして挙動を観察してみてください。
