# Breaking Enigma with Index of Coincidence on a Commodore 64 - コモドール64で「一致指数」を使ってエニグマを解く

魅力的な日本語タイトル: 秘密鍵（クリブ）なしでエニグマを暴く――コモドール64で「言語の指紋」を使った古典暗号ハック

## 要約
古典的手法「Index of Coincidence（一致指数、IC）」を使えば、既知平文（クリブ）が無くてもエニグマのロータ設定を絞り込める。コモドール64上でも整数演算だけで実用可能で、短文でも人間の目で判別できる候補にまで絞れる。

## この記事を読むべき理由
エニグマの実践的解析手法をレトロPCで動かす事例は、暗号解析の基本原理（統計で言語を識別する）を学ぶ絶好の教材。日本のレトロPC／暗号好き、セキュリティ入門者にとって理解しやすく即試せるテクニックです。

## 詳細解説
- アイデアの核心  
  Friedmanの一致指数は「ランダムな文字列と自然言語の統計的差」を利用する手法。英語やドイツ語の文字頻度は一様でなく、任意の2文字が一致する確率（IC）は自然言語で約0.066〜0.076、完全ランダムで1/26≈0.0385になる。この差を手がかりに、復号結果が「言語らしいか」を判定する。

- 数式（一致指数）  
  $$IC=\frac{\sum_{i=0}^{25} n_i(n_i-1)}{N(N-1)}$$  
  ただし $n_i$ は文字iの出現回数、$N$ は総文字数。C64実装では割算不要で分子（IC sum）だけ計算し、閾値と比較する実装が簡単＆高速。

- プラグボードが敵ではない理由  
  プラグボードは単純置換でラベルを入れ替えるだけ。各文字の「頻度の大きさ」は変わらず、ICは不変。よってIC攻撃はロータ順・位置（約5.9百万候補）をまず絞り、残った候補でプラグボードを個別解析する戦略が有効。

- 実際の数値例（抜粋）  
  60文字の鍵なら閾値IC≥0.050に対応するIC sumは $0.050\times60\times59=177$。記事の例では正解設定の復号がIC sum=258（可読なドイツ語）で、単一ロータ順（17,576位置）に対して閾値177では286候補に絞られた。全336ロータ順で厳しめの閾値194（IC≥0.055）にすると候補数を管理可能にするが、正解は候補群の中で必ずしもトップに来ない（短文だと統計ノイズで上位に偽陽性が来る）。

- 計算コスト  
  クリブを使う総当たりと違い、IC法は文字列全体を復号して頻度を数えるため1候補あたりメッセージ長分の暗号化コストがかかる（例：60文字なら60回の暗号化）。ただしクリブ不要という大きな利点がある。

- 実用上の注意  
  短文（60字程度）は偽陽性が多く、人間の目で可読性を判定する必要がある。200文字以上であればICが安定して正解が上位に来る傾向が強い。自動化するならバイグラム頻度や辞書照合で追加フィルタを掛ける。

簡易擬似コード（各ロータ順に対して）：
for each start position:
  decrypt whole ciphertext
  count frequencies n_i
  compute S = sum n_i*(n_i-1)
  if S >= threshold: report candidate

参考に、ICの分子（IC sum）を計算する短いPython例：

```python
# python
def ic_sum(text):
    from collections import Counter
    counts = Counter([c for c in text.upper() if 'A'<=c<='Z'])
    N = sum(counts.values())
    return sum(v*(v-1) for v in counts.values()), N
```
