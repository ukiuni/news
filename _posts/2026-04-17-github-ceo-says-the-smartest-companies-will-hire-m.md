# GitHub CEO says the ‘smartest’ companies will hire more software engineers not less as AI develops - GitHub CEO「賢い企業ほどAIでエンジニアを減らさず増やす」と語る
AIで“エンジニア不要論”は誤解？生産性を倍化するAI時代に、採用とスキル投資で勝つ企業の条件

## 要約
GitHub CEOのトーマス・ドームケ氏は、AIは開発者を置き換えるのではなく生産性を倍増させ、結果的にソフトウェア全体の量が増えるため「賢い企業ほどエンジニアを増やす」と主張している。

## この記事を読むべき理由
AI普及で「人員削減か？」と不安な日本の開発現場に対し、採用・教育・プロダクト戦略の現実的な示唆を与える。DXや人手不足が課題の日本企業にとって、AIをどう業務や組織に組み込むかの指針になる。

## 詳細解説
- AIは「代替」ではなく「倍化」：Copilotのような生成AIは個々の開発者の生産性を大きく引き上げる。ドームケ氏は「1人を10倍にすれば10人で100倍になる」と例え、総コード量・可能性が増えるため、結果的に開発者需要は増加すると説明している。  
- Vibe coding／ノーコードの限界：プロンプト操作で簡単なアプリは作れるが、性能最適化、スケーラビリティ、バグ修正、アーキテクチャ設計などは依然として深い技術力を要する。AIだけでは限界に直面する場面が多い。  
- 学習の民主化と“天井”：AIは学習の障壁を下げ、初心者が早く成果を出せる。だが高度な問題解決能力は実践的なコード理解とデバッグ経験が必要で、学習の最終目標は“AIを使いこなす力”となる。  
- 業務負荷とバックログ：興味深い点としてAIはバックログを解消していない。むしろ可能性が増え、やるべきことが増えるため、優先順位と人員計画が重要になる。  
- 次世代とスキルの分化：将来は「消費者的にツールを作る人」から「インフラやAI基盤を作るプロ」まで幅広い開発者像が共存する。

## 実践ポイント
- 今すぐ試す：GitHub CopilotやChatGPTで日常のコーディング支援を試し、チームでの標準ワークフローに組み込む。  
- 基礎に投資：アルゴリズム、設計、テスト、デバッグ能力はAI時代でも不可欠。教育プログラムを整備する。  
- プロンプト設計を学ぶ：効果的なプロンプトは生産性の鍵。社内に「AIオーケストレーター」を育てる。  
- 採用戦略を見直す：AIで生み出される仕事量を踏まえ、中核人材と補助的役割をバランス良く採用する。  
- 優先順位管理：AIで可能になったアイデアをすべて実行すると混乱するため、バックログ管理とスコープ設計を強化する。

以上を踏まえれば、日本企業でもAIを「脅威」ではなく「成長のエンジン」として取り込める。
